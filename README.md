# アクセンチュア CEOインターン支援プロジェクト

このフォルダは、7週間のインターンについて、Notionでの進行管理、資料理解、環境構築の整理、分析設計、報告準備をCodexと進めるための運用起点である。

## 作業前に読む文書

1. `COMPANY_INFORMATION_HANDLING.md`
2. `INTERNSHIP_PROJECT_BRIEF.md`
3. `INTERNSHIP_TASKS_02_03.md`

情報管理ルールと会社の正式資料が、利便性や作業速度より常に優先される。

## 最優先の情報境界

- 会社情報、実データ、顧客・個人情報、認証情報、内部URL・内部IDを、このフォルダ、Notion、Codexのチャット、個人クラウドへ保存しない。
- 会社PC、会社ネットワーク、会社指定クラウドは、この個人PC上のCodexから接続・操作しない。
- 社内資料の本文・画像・スクリーンショットを複製・転載しない。
- 外部検索では会社固有の情報を使わず、一般化した製品名・技術用語だけを検索する。
- 判断に迷う場合は作業を止め、運営・メンターへ確認する。

## Notionの運用範囲

編集対象は、就活ワークスペースの `アクセンチュアCEO` とその配下に限定する。

- `マニュアル・注意事項まとめ`
  - `セットアップ関連`
    - `Zaim環境設定`
    - `SageMaker環境設定`
  - `注意事項`
  - `プログラミング実践`
    - `SQLの基本｜RedshiftからS3への保存`
    - `Pythonの基本｜JupyterLabでの分析`
    - `SQL・Python 発見ログ`
- `スケジュール・タスク管理`
- `テーマ選定`
- `何気ない議論たち`
- `提出用資料`

それ以外のNotionページは参照・編集しない。Notionを変更するときは、対象ページとデータベースの現行内容・スキーマを取得してから編集し、反映後に再取得して確認する。

## Notionページの役割分担

`スケジュール・タスク管理` は、予定と実績を管理する正本として使う。タスクそのものの手順、分析内容、議論、調査結果、コード解説、成果物本文はここへ蓄積せず、内容に合う専用ページへ記録する。

| 記録する内容 | 編集先 | スケジュール側に残すもの |
|---|---|---|
| 期間、週、状態、実績開始日、完了日 | `スケジュール・タスク管理` | 予定・進捗・実績 |
| タスクの目的、完了条件 | `実行タスク一覧` の各タスクページ | チェック可能な完了条件 |
| VPN、Redshift、SageMakerなどの設定手順・概念・用語 | `マニュアル・注意事項まとめ ＞ セットアップ関連` | 対応するタスクと詳細ページへのリンク |
| セキュリティ、データ・LLMの取扱ルール | `マニュアル・注意事項まとめ ＞ 注意事項` | 確認タスクと詳細ページへのリンク |
| SQL・Pythonの基本、実行例、発見事項 | `マニュアル・注意事項まとめ ＞ プログラミング実践` | 学習・確認タスクと詳細ページへのリンク |
| テーマの比較、最新版の判断、選定理由、選定過程 | `テーマ選定` | テーマ決定タスクと詳細ページへのリンク |
| 会話から生まれた横断的な論点・仮説・方針 | `何気ない議論たち` | 必要な場合だけ関連タスクへのリンク |
| 提出物の名称、作成日、Google資料へのリンク | `提出用資料` | 資料作成・提出タスクと資料ページへのリンク |
| Step 0以降の調査、分析、原因分析、施策立案の詳細 | 対応する専用ページ | タスクには進捗、完了条件、専用ページへのリンクだけを残す |

### タスクと詳細ページの対応付け

- タスクページの本文は、原則として「目的」「完了条件」「関連ページ」「実績メモ」だけにする。
- 詳細な手順、調査記録、分析コード、分析結果、議論本文は、内容に合う専用ページへ置く。
- タスクに対応する詳細ページがある場合は、タスクページの `関連ページ` からリンクする。詳細ページ側にも、必要に応じて対応するタスクへのリンクを置く。
- 専用ページがまだない場合は、詳細内容をスケジュールページへ仮置きしない。既存の格納先を確認し、該当先がなければ `アクセンチュアCEO` 配下に専用ページを用意してから記録する。
- タスクを作成・更新するときは、同名・同目的の詳細ページがないか確認し、リンク切れ、重複ページ、対応漏れがないことを読み戻して確認する。

## 現在のNotion設計

### セットアップ関連

- `Zaim環境設定`：貸与Windows、VPN、RDP、分析用Windows、Redshift、S3、SageMakerの接続・データフローを概念図で表示する。
- `SageMaker環境設定`：JupyterLab、Code Editor、作業フォルダ、Claude Code、Amazon Bedrock、Claudeモデルの包含関係を概念図で表示する。
- 概念図には認証値、内部IP、内部URL、モデル内部IDを含めない。

### スケジュール・タスク管理

- タスクDBを予定・進捗・実績の正本とし、タイムライン、予定カレンダー、今週のタスク、状態ボード、実行済みログで表示する。
- 計画時は `期間`・`週`・`状態` と、各タスクページの完了条件を入力する。
- 着手時は `状態=進行中` と `実績開始日` を入力する。
- 完了時は、タスクページの完了条件をすべて確認してから `状態=完了`・`完了日` を揃え、`実績メモ` に予定との差や次の引継ぎを残す。
- 手順や分析結果の本文はタスクDBへ書き込まず、対応する専用ページへリンクする。
- 週初に `今週のタスク` ビューの `週` フィルターを現在週へ切り替える。

### テーマ選定

- ページ上部に最新版の意思決定、理由、未確認条件を表示する。
- 各議論は `テーマ選定 議論ログ` に1ページずつ追加する。
- 根拠だけでなく、反証、判断への影響、次に確認することを残す。

### 何気ない議論たち

- Codexとの会話から生まれた疑問やアイデアは `何気ない議論ログ` に1論点1ページで記録する。
- 各ページは「会話の要点」「現時点の結論」「次アクション」を基本形とする。
- 記録前に機密確認を行い、会社情報を含む場合は保存せず、一般化する。

## Codexとの進め方

1. ユーザーと論点・目的を確認する。
2. ローカル文書と、指定されたNotionページの現行状態を確認する。
3. 内容を「スケジュール・進捗」か「タスクの詳細内容」かに分類し、上の役割分担表から編集先を決める。
4. タスクと詳細ページの対応関係を確認し、必要な相互リンクを設定する。
5. 事実、仮説、未確認事項を分けて提案する。
6. Notionへ残す場合は、会社情報を除いた最小限の内容だけを記録する。
7. 変更後にページ、親子関係、DB行・ビュー、関連ページへのリンクを再取得する。
8. 変更点と未確認事項をユーザーへ報告する。

## 会社環境の成果をCodexへ相談するとき

会社PC内のコード・分析ファイル・データを、個人PCのCodexへ直接移さない。まず会社環境内の許可されたツールでレビューし、外部相談が必要な場合は、運営・メンターの事前承認を得たうえで、架空データ、一般化した疑似コード、秘密情報を除いた最小再現例など、許可された粒度だけを使う。
